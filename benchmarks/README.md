# 自对弈调试

`self-play-v2.mjs` 使用正式裁判，并通过 Node 工作线程执行冻结源码中的 `ai-worker.js`。认输预检、剩余搜索预算分配和落子使用同一个桌面决策入口。双方仅接收各自的公开观察、自己的棋子及局内风格；不会把裁判棋盘、对方阵型种子或复盘真值传给走棋程序。职业总预算约 900 毫秒，地狱约 5 秒，认输检查占用其中的时间。实际搜索深度、节点数和用时逐手记录；工作线程的通信耗时另计，剩余预算不代表实际搜索耗时。

工具冻结并核对源码目录下的全部 JavaScript 文件，同时绑定自对弈入口与线程适配器。新棋谱和单个赛程报告使用 schema 2，注明 `desktop-worker-v1`。旧 schema 1 赛程报告仅供历史追溯和排除已使用的种子，不能混入当前验收或用新工具续跑。测试注入的走棋程序始终标为 `testOnly`，不能通过棋力验收。

每个种子打两局。双方各自保留按难度生成的阵型，旋转棋盘、交换先后手。默认种子池区分调试与验收。对局文件写入报告旁的 `.games` 目录，可重放每一步；不会写入桌面游戏的玩家经验文件。

调试示例：

```powershell
node benchmarks/self-play-v2.mjs --mode training --opponent professional --games 2 --seeds 301001 --max-plies 320 --output benchmarks/training-301001.json
node benchmarks/self-play-v2.mjs --mode training --opponent hell --games 2 --seeds 303001 --max-plies 320 --output benchmarks/training-303001.json
```

需要继续中断的对局时，在原命令后加 `--resume`。程序会重新校验源码、初始阵型、每一步棋及裁判结果；修改 AI 后应使用新报告，不得把不同版本混成一次验收。`--source-root` 可选择冻结的 `dist` 副本。认输决定单独保存公开观察哈希、证明和实际耗时，不伪造一次落子；复核时从重放所得的公开局面重新验证必败，不能只相信报告中的认输标记。

验收要求：冻结同一版本；用未用于调参的 10 个种子交换先后手，完成 20 局真实终局；地狱至少 19 胜。规则终局与经过公开证明复核的认输终局分别统计。和棋不算胜，步数封顶不算和棋或胜利，错误与未完成对局不能通过。所有结果保留，不能挑选胜局、以子力领先判胜或降低职业水平凑分。

`self-play-batch.mjs` 支持 `--jobs 4` 并行独立种子，在启动前保存完整计划，结束后逐局重放核验。它采用与单进程工具相同的 AI 时间预算。正式验收必须提供 `--expected-sha` 和完整的 `--training-reports` 来源清单；看过并用于调参的旧验收棋局也应从之后的验收种子中排除。

自对弈用于发现问题和验证代码改进。当前工具不会自动训练神经网络，也不会把模拟对手的习惯混入玩家的历史经验。达到一次 19/20 是本任务的验收条件，不等于保证以后每组比赛都能取得相同胜率。

本工具验证冻结 JavaScript 在 Node 工作线程中的对弈；它不代替 Windows EXE 的实际打包检查、界面验证或启动性能测量。短局和定向续弈只能说明所覆盖的执行流程，不能作为完整棋力战绩。

新报告可由批处理验证器逐步重放。本机另有只支持旧 schema 1 的历史分析器，未随本仓库发布；自动提取战术样本仍需适配独立认输事件，不能强改 schema 绕过检查。
